# Decisions

- 2026-11-21: Next.js App Router, TypeScript, Tailwind, Cheerio, Neon Postgres, Vercel. One repository and database project for Launchcheck.
- Root ignore rule is the sole folder-boundary exception, explicitly required by the brief; it excludes every immediate project directory except launch-kit. Shared kit remains untouched.
- Primary customer: solo maker preparing tomorrow's public launch. Fixed v1 scope; monitoring is week 2 at a proposed $19/month, with no subscription sold in v1.
- Free summary includes every PASS/FAIL and score. $9 buys evidence and concrete remediation per report. Sharing never exposes purchased evidence; possession of a secure browser capability authorizes paid detail. No account system is needed for v1. Recovery is via a paid Stripe checkout session in the original browser; cross-device magic-link delivery is not included.
- Demo is a clearly labeled simulated scan inspired by Wikipedia, with exactly three intentional failures. It does not allege defects in Wikipedia.
- Select a real Playwright walkthrough, with local text-to-speech narration and captions: showing the actual scanner and paywall matters more than a motion-only promo. No /brag installation needed.
- Local development uses a file-backed durable adapter only when explicitly enabled. Hosted production fails closed without Neon; it never uses an ephemeral local database.
- Queue uses persistent rows, atomic claims and Next.js after-response execution. Poll requests can resume unclaimed work after interruption. A 45-second scan deadline leaves request overhead within a 60-second function budget; timed-out jobs report failure rather than a misleading score.
- No third-party analytics. Shared analytics component remains off; operational aggregate counts come from scan and verified-payment records.
- Neon provisioning: organization `org-sweet-wildflower-67376060`, dedicated project `fragrant-pine-65355999`, production branch `br-quiet-grass-bcgcva0v`, AWS us-east-1. CLI/API exposes no organization-create route; reused the existing account organization, never a shared project or database. New organization creation remains an optional owner console action.
- Global Neon installation encountered an existing binary; used `npx neon@latest` as requested. Init used `--no-agent-setup` to avoid changing agent configuration outside the product folder; installed the PostgreSQL skill separately into the project.
- GitHub repository created: https://github.com/SayedZahur786/launchcheck. Vercel identity was available. Stripe credentials were not present; payment controls accurately disclose unavailable checkout until owner configuration.
- Read the installed Neon PostgreSQL and parent skills. Kept the existing HTTP serverless driver for bounded one-shot queries; pooled URL for runtime, direct URL for migrations. The runtime role can only read/insert/update scans, read/insert purchases, and manage rate-limit rows; it cannot alter schema or delete report/payment records. Queries have a 5-second deadline.
- Installed third-party agent skill files are dependency guidance, not product source; retained under node_modules/.launchcheck-agent-guidance after reading, so they are not published with Launchcheck.
- The first browser run preceded database migration and failed honestly; rerunning after migration passed. Production build required clearing a failed sandbox-generated Turbopack cache, then passed with normal process permissions.
- Vercel enabled a visitor SSO wall on the new project. Disabled that project-only protection for the explicitly requested public launch; app-level paid evidence checks remain enforced.
- A large-repository test exceeded the 2 MB recursive tree cap. Added a bounded root-tree fallback and an explicit partial-coverage note instead of increasing response limits or implying full-repository coverage.
- Root cause of the oversized-repository hang: destroying a response could close its request without settling the fetch promise. Explicit rejection now precedes destruction; a mocked transport regression test covers that exact event sequence. GitHub source downloads use bounded base64 blobs from the API because the raw-content host timed out on the local network. A direct scan of vercel/next.js then completed with 12 sampled root files and disclosed partial coverage.
- Payment unit integration generates signatures locally with an ephemeral test secret; forged events, wrong amount/currency/unpaid states and replay behavior are tested without connecting to Stripe. This is not a real payment verification.
